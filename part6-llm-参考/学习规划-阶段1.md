# 第一块：先让它跑起来

## 里程碑 0 · 确定厂商，拿到钥匙

**做什么**

1. 选定一家模型厂商（有免费额度的优先，够你练手）。常见的几家：

| 厂商 | base_url 大致格式（**以官方文档为准**） | 备注 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | 便宜、中文好，入门常用 |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | 常有免费额度 |
| 月之暗面 Kimi | `https://api.moonshot.cn/v1` | 长上下文见长 |
| 阿里通义 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 注意走"兼容模式"这个地址 |
| 百度文心 | `https://qianfan.baidubce.com/v2` | |

   > 模型名和地址会变，**一定去厂商控制台和接入文档确认当前的值**。顺便确认一件事：它是否提供 "OpenAI 兼容" 接口——兼容的话，同一个 SDK 能通吃所有厂商，这是后面省事的关键。

2. 注册、创建 API Key，记下三样东西：**base_url、模型名、Key**。
3. 把这三个值填进 `part6-llm/.env`。
4. 安装 `openai` 这个 SDK。

**怎么算过了**

- 本地能 `import openai` 不报错
- `.env` 里的值能被读出来（但**别把 Key 打印出来**）
- 你能说清楚：为什么 `.env` 必须写进 `.gitignore`

**几个必须知道的坑**

- Key 通常**只在创建时显示一次**，错过了就得重建。
- Key 不要提交到 git，不要贴到聊天里，**也不要发给我**。它相当于你的银行卡密码。
- 付费接口记得去控制台设消费上限，避免手滑跑飞。

## 里程碑 1 · 跑通第一次调用

**学什么**

- SDK 客户端的构造：为什么需要传 base_url 和 api_key
- `messages` 是什么：为什么是"一串 message"而不是"一句话"
- `role` 是什么：system / user / assistant 三种角色各自代表谁说的话
- 为什么这类接口叫"聊天接口"而不是"文本续写接口"

**做什么**

- **先别碰 FastAPI。** 写一个最简单的独立脚本：给模型发一句话，把回复打印出来。
  一次只引入一个新变量，是最省事的排错方式。
- 把**整个响应对象**完整打印出来看一遍，找出：回复文本在哪个字段、用了多少 token 在哪个字段。

**怎么算过了**

能回答这三个问题：

- 这次请求实际发出去的 JSON，大概长什么样？
- 响应里有哪些字段？哪个才是模型真正的回答？
- 如果报错，怎么一眼看出是 **401（Key 不对）**、**404（地址或模型名不对）** 还是超时？

## 里程碑 2 · 搞懂 token、上下文和生成参数

这一节**不写项目，只做实验**。这是你路线图"同期理论"那一栏要求的内容。

**学什么**

- token 是什么（它既不是字，也不是词）
- 为什么同样的意思，中文和英文消耗的 token 数不一样
- 上下文窗口是什么，超了会怎样
- `temperature`、`max_tokens`、`top_p` 分别控制什么

**做什么（三个实验）**

1. **token 实验**：同一句话分别用中文和英文问，对比返回的 token 用量。
2. **temperature 实验**：把 temperature 调到 0 和调到 1.5，各问同一个开放性问题几次，观察回答的差异。
3. **max_tokens 实验**：故意设一个很小的值，看回复被怎么处理。

**怎么算过了**

- 能用自己的话解释 token 和上下文窗口
- 能说出 temperature 调高、调低分别会发生什么
- 能说出 max_tokens 设太小的后果
- 能解释：为什么这些参数会影响你的话费和速度

# 第二块：核心能力

## 里程碑 3 · 多轮对话（上下文管理）

**学什么**

- ⭐ 模型本身是**无状态**的：它不记得你上一条说了什么
- 那"多轮对话"是怎么实现的？（想清楚这一点，你就理解了一半的 Agent 原理）
- system 消息的作用：给模型设"人设"

**做什么**

- 写一个**命令行多轮对话小程序**：能连续聊、能退出、聊的时候它记得前面说过的内容
- 给它设一个 system 人设（比如"你是我的 Python 学习助手"），对比有无人设时回答风格的差异
- 故意聊很多轮，观察每次请求的 token 数是**怎么变化的**

**怎么算过了**

- 能解释"为什么第二轮必须把第一轮的消息一起发过去"
- 能回答"上下文快满了该怎么办"（提示：你要维护的那个列表，以及怎么让它"忘记"最早的对话）
- 能说出为什么这样设计会导致话费随对话长度**不断上涨**

> 挂钩：你在 `part5-进阶/闭包.py` 里用 `nonlocal` 保存状态，这里是另一种"保存状态"的方式。
> 想一想两者的区别。

## 里程碑 4 · 结构化输出（本阶段的重头戏）

**学什么**

- 什么叫结构化输出：让模型返回**机器能直接用的 JSON**，而不是一段自然语言
- JSON Schema 是什么
- ⭐ **为什么模型给的 JSON 不能直接相信**（它可能多说一句话、少写一个字段、把格式写坏）
- 校验失败时怎么办：重试？兜底？还是报错给用户？

**做什么**

- 给模型一段**非结构化文本**（比如一条口语化的订单描述），让它抽取成固定字段的 JSON
- 用 **Pydantic** 定义你想要的形状，去接住模型的输出并校验
- 故意喂一个会让它出错的输入，看校验怎么把问题抓出来
- 处理"模型返回的根本不是合法 JSON"这种情况

**怎么算过了**

- 能说清"模型**说**它返回了 JSON"和"它**真的**返回了合法 JSON"这两件事的区别
- 你的程序遇到坏 JSON 不会直接崩
- 能说出：如果模型连续三次都返回坏格式，你的程序应该怎么收场

> 挂钩：这就是你 `part3-mysql/数据分析案例/` 里 `Record` 类那套思路——先定义好数据长什么样。
> 区别是这次数据是模型生成的，所以更不可信。

## 里程碑 5 · 组织成模块 + 配置外置

**学什么**

- 为什么要分层：配置 / 模型调用 / 接口 各管各的
- 为什么配置要放环境变量（你在 `mysql.py` 里把密码写死那个坑）

**做什么**

- 把前面几个里程碑写的东西**整理成独立的模块**：一个专门管"调用模型"的文件、一个管配置的、一个管数据形状的
- 配置全部从 `.env` 读
- 做一次验证：**换一个模型名（或换个厂商），只改 `.env`，代码一行不动**

**怎么算过了**

- 能做到"改配置不改代码"
- 能说清楚每个文件负责什么、为什么这样分

# 第三块：工程化

## 里程碑 6 · 异步 async / await

**学什么**

- "IO 密集"和"计算密集"的区别
- `async` / `await` 到底在做什么：等网络的时候把执行权让出去
- 为什么 FastAPI 里这件事特别重要
- 你学过的 `threading` 多线程 和 async 的区别、各自适合什么场景

**做什么**

- 把模型调用改成 async 版本
- 写个小实验：**同时发 5 个请求**，对比同步版和异步版各花多久

**怎么算过了**

- 能解释"等网络"和"做计算"为什么要用不同的方式处理
- 能说出多线程和 async 的取舍
- 实验结果确实显示出异步更快（如果没快，想想为什么）

## 里程碑 7 · 接成 FastAPI 接口

**学什么**

- 请求模型和响应模型（Pydantic）
- FastAPI 里 `async def` 的意义
- 怎么把 Python 异常转成合适的 HTTP 状态码

**做什么**

- 把模型调用包成一个 POST 接口：请求体是消息列表，响应是模型回复
- 加上**超时**处理（模型太慢怎么办）
- 加上**重试**（偶发网络失败怎么办）
- 加上**耗时记录**（每次请求花了多久）
- 给三种失败情况分别设计返回：Key 无效、超时、模型返回格式错

**怎么算过了**

路线图的四条验收标准，逐条过：

1. ✅ 正常请求能完成
2. ✅ 超时 / 参数错误 / 格式错误 都能被处理
3. ✅ 有请求耗时记录
4. ✅ 能用固定样例比较两种模型或两种提示词

# 里程碑 9 · 阶段验收

**做的事**

- 用**固定的一组样例**，比较两种模型或两种提示词（路线图原文要求）
  - 比如：同一个任务，问 5 个问题，记录两家模型各自的回答质量、耗时、token 花费
  - "固定"很重要：不固定样例，你就没法比较

**交付物清单**

- [ ] 一个能跑的对话后端（FastAPI 接口）
- [ ] 一个结构化输出模块（Pydantic 校验）
- [ ] 一份配置说明（怎么配 Key、怎么换模型）
- [ ] 一份测试
- [ ] 一份对比记录（两种模型/两种提示词）

**最后自测：能独立回答这六个问题**

1. 一次模型调用，从头到尾发生了什么？
2. token 是什么？上下文窗口是什么？为什么会限制你？
3. 模型到底记不记得上一轮？"多轮对话"是怎么实现的？
4. 为什么要用 Pydantic 校验模型的输出？
5. async 解决的是什么问题？它和多线程有什么区别？
6. 你的程序在 Key 错 / 超时 / 格式错 时，分别会怎样？

**这六个问题能不打草稿讲出来，第一阶段就算过了。**
